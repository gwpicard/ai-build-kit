![AI Build Kit: build tools you can maintain without reading code](/ai-build-kit/hero.jpg)

AI Build Kit helps people who do not write code build tools with a coding agent, a program that reads and changes project files. It is intended for people who can create accounts and follow technical setup instructions.

You describe the tool, and the agent builds one agreed piece of work at a time. A piece is a change small enough to build in one session. You try each change and decide whether to merge it into the main branch, the project’s main line of development. A branch is a separate line of work; merging incorporates its changes into another branch.

## Why this kit

The person who needs an internal tool usually knows best what it should do, and often only discovers the details while building it. AI Build Kit lets that person build the tool and keep it running without reading code.

- **It's yours.** Each tool built on a recipe is a standard Next.js and Supabase project in your GitHub, running on Vercel or on a server you rent and manage with Coolify, which can host several tools on one machine.
- **It lasts.** The agent's work goes through scripted checks and a second agent's review, and you try each change before deciding whether to merge it. Each recipe defines launch, backup and rollback steps; its `PROVEN.md` record lists which steps have run on a live host.
- **You get better at it.** Every change starts as a small piece of work with written acceptance criteria, so you learn to specify and lead the build.

[How it differs](/ai-build-kit/how-it-differs/) compares the kit with hosted app builders such as Lovable and Replit, and with skill sets written for developers.

See the guide to [working with the kit](/ai-build-kit/working-together/), [maintaining a tool](/ai-build-kit/maintaining-your-tool/) and [live data and recovery](/ai-build-kit/live-data/).

## What happens

1. You describe the tool. A setup script checks that Git and Python 3 are available and that you are signed in to GitHub. The agent checks access to your repository, where the project files and their history are stored.
2. You agree on a piece, and the agent records its acceptance criteria under “Done when”. These describe the result you will use to judge the work.
3. The agent builds the piece, scripts check the change, and a reviewer agent assesses the result.
4. You try the change and tell the agent to merge the named pull request, a proposal to merge it into the main branch. The agent records your approval, and the merge script checks it and the project check result.
5. To put the tool live, you choose a [hosting recipe](/ai-build-kit/recipes/): a fixed stack and host with steps for previewing, launching, backing up, restoring and rolling back. On a recipe, the launch script holds its live-address record when a backup is unconfirmed or no way back is defined. It does not stop a host that deploys on merge.

The checks provide evidence about the tool, but they do not establish that it is safe for every purpose. Some work may still need a developer. Read [the design principles](/ai-build-kit/design/) and [what the kit checks](/ai-build-kit/what-it-checks/).
