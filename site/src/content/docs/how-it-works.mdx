Setup comes first. For each piece, you and the agent agree scope, it builds the change, a reviewer checks it, and you decide whether to merge. You can rerun hosting setup.

## Step by step

### Set up a project

**What happens:** In the founding interview, you describe the tool, its users, work and risks. The agent records its purpose and risks in the masterplan, creates the first GitHub issues and saves a local checkpoint.

See the [setup instructions](https://github.com/gwpicard/ai-build-kit/blob/stable/.agents/skills/setup-ai-build-kit/SKILL.md).

**What you decide:** You answer the interview questions and decide whether to use existing work.


### Shape a piece

**What happens:** You and the agent define one piece and agree on its acceptance criteria.

**What the labels mean:** `ready` marks work ready to build; `needs-answers` marks an open question. A `Reaches:` line lists code areas the piece may change.

See the [shape instructions](https://github.com/gwpicard/ai-build-kit/blob/stable/.agents/skills/shape/SKILL.md).

**What you decide:** You resolve open questions and decide whether to run `/implement`.


### Implement a piece

**What happens:** The agent builds one ready piece on its own branch.

See the [implementation instructions](https://github.com/gwpicard/ai-build-kit/blob/stable/.agents/skills/implement/SKILL.md).

**What you decide:** By default, you try the result and tell the agent to merge the named pull request; it records your approval. Automatic merging is off unless enabled. It requires three previous approved merges and a dated `Runs on its own:` entry in the masterplan, and acts within those limits.


### Review the change

**What happens:** A reviewer agent assesses the change and evidence in a separate session, without the builder’s conversation history.

See the [review instructions](https://github.com/gwpicard/ai-build-kit/blob/stable/.agents/skills/second-opinion/SKILL.md).

**Second review:** A fresh reviewer tries to refute each "worth stopping for" finding before it is recorded.

**What you decide:** You choose which findings to fix and can ask for an explanation. An open "worth stopping for" finding blocks the merge.


### Merge the change

**What happens:** By default, the agent asks you in conversation to approve merging the named pull request, records your words and date, then runs the merge script.

See the [merge instructions](https://github.com/gwpicard/ai-build-kit/blob/stable/.agents/skills/merge/SKILL.md).

**What you decide:** Your approval covers only the pull requests it names and each recorded approval is used once.


### Set up or check the live tool

**What happens:** The agent sets up hosting or checks the live copy.

See the [hosting instructions](https://github.com/gwpicard/ai-build-kit/blob/stable/.agents/skills/setup-hosting/SKILL.md).

**What you decide:** Decide whether to launch after the agent explains the change. [Hosting recipes](/ai-build-kit/recipes/) define launch, backup and rollback steps; outside one, the kit gives no guarantees ([design reasons](/ai-build-kit/design/#host-only-on-recipes-that-have-been-tried)).

### Maintain the project

**What happens:** The agent checks project records and the live copy (the running tool on its host), then runs monthly or quarterly upkeep when due.

See the [maintenance instructions](https://github.com/gwpicard/ai-build-kit/blob/stable/.agents/skills/maintain/SKILL.md).

**What you decide:** After its report, you decide whether to apply changes beyond routine record updates.
