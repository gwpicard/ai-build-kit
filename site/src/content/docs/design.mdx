## Why the kit exists

A coding agent can make a working prototype quickly, but it is hard to maintain if nobody knows where its data lives or how to recover from failure. The kit offers a way to build and maintain tools without reading code.

The kit suits internal tools for teams, clubs, families or invited clients. A hosted builder may suit you better if you want an app quickly and do not want to use GitHub. The kit does not teach programming or replace a needed developer.

## Design choices

### Agree on one piece at a time

Before building, you and the agent agree on a piece’s acceptance criteria under "Done when". Keeping each piece small gives you a defined change to try. See the [shape step](/ai-build-kit/how-it-works/#shape-a-piece).

### Use machine checks where the rules can be tested

Scripts check rules with testable conditions. Hooks run automatically at particular events. Written instructions guide decisions that need judgement ([philosophy](https://github.com/gwpicard/ai-build-kit/blob/stable/docs/PHILOSOPHY.md#what-earns-a-place)).

### Keep instructions short

The kit retains rules only when a machine enforces them, measurements support them or they require judgement ([philosophy](https://github.com/gwpicard/ai-build-kit/blob/stable/docs/PHILOSOPHY.md#small-is-a-reliability-feature)).

### Warn once when you can judge the risk

For risks you can judge, the agent explains who could be affected and what caution, or safeguard, would normally prevent harm. You decide whether to take it or accept the risk; the agent records your decision and date. Each piece names the risks it creates ([risk design](https://github.com/gwpicard/ai-build-kit/blob/stable/docs/PHILOSOPHY.md#the-risk-concept)).

### Keep the tool in your accounts

Your code, hosting and database are in accounts you control. You can change coding agent, host or developer without losing ownership ([philosophy](https://github.com/gwpicard/ai-build-kit/blob/stable/docs/PHILOSOPHY.md#what-the-kit-is)).

### Host only on recipes that have been tried

Hosting guarantees apply only on a [recipe](/ai-build-kit/recipes/), a fixed stack and host run on real accounts. Each recipe defines backup and rollback steps; its record lists which have been tried. Neither recipe has had a real backup or restore run. Outside a recipe, the kit gives guidance but no guarantees ([philosophy](https://github.com/gwpicard/ai-build-kit/blob/stable/docs/PHILOSOPHY.md#what-the-kit-is)).

### Test outcomes

The kit’s tests judge what the agent does, not what its instructions say. Shell checks test its scripts and boundaries. Replays grade what the agent did and saved in scripted conversations ([testing](https://github.com/gwpicard/ai-build-kit/blob/stable/docs/PHILOSOPHY.md#testing-the-kit)). They do not prove that every tool is safe for every purpose.
