AI Build Kit helps a person build and run a tool with a coding agent without needing to read code. It is for people who are comfortable with technology but do not write code. A developer who is new to agent-led work may use it too.

## Principles

**One agreed piece at a time.** Each piece has a result the person can check. The person agrees to that result before an agent builds it.

Where it holds: [shape skill](https://github.com/gwpicard/ai-build-kit/blob/stable/.agents/skills/shape/SKILL.md).

**The person decides, and the kit explains.** By default, the person tries the result and decides whether to approve the change for merge. Automatic merging is an option with recorded limits.

Where it holds: [merge skill](https://github.com/gwpicard/ai-build-kit/blob/stable/.agents/skills/merge/SKILL.md).

**A machine holds a rule wherever it can.** Hooks, settings and scripts apply rules each time. Prose explains only the judgements a machine cannot make.

Where it holds: [what the kit always holds](/ai-build-kit/what-it-checks/#what-the-kit-always-holds) and [maintaining guide, backbone and mechanisms](https://github.com/gwpicard/ai-build-kit/blob/stable/docs/MAINTAINING.md#the-backbone-and-its-mechanisms).

**A sentence earns its place only if a machine enforces it, a replay shows it changes the outcome, or it carries a judgement.** Rules based on one failed run remain hypotheses until a measurement backs them.

Where it holds: a judgement, not a check.

**Small is a reliability feature.** Every instruction competes for the agent's attention. A rule that does not help makes the important rules less likely to be followed.

Where it holds: [the size check](https://github.com/gwpicard/ai-build-kit/blob/stable/.agents/tools/check-structure.py), which fails a skill or reference that grows past its word limit.

**Warn once, then respect the decision.** The kit names a risk and explains who could be exposed and what would normally prevent harm. The person chooses what to do, and the kit records their words and the date.

Where it holds: [fit-check skill](https://github.com/gwpicard/ai-build-kit/blob/stable/.agents/skills/fit-check/SKILL.md).

**Build tools the owner can run and share.** Each project can go live and be shared with a team. Its repository, host and database accounts belong to the owner.

Where it holds: [setup skill](https://github.com/gwpicard/ai-build-kit/blob/stable/.agents/skills/setup-ai-build-kit/SKILL.md) and [hosting recipes](https://github.com/gwpicard/ai-build-kit/blob/stable/.agents/skills/setup-hosting/SKILL.md).

**Test what the kit does, not what it says.** Shell checks test boundaries and scripts. Replays check what the agent did and what it left in the project.

Where it holds: [kit tests](https://github.com/gwpicard/ai-build-kit/tree/stable/.agents/tests).

## Why the kit exists

A coding agent can make a working tool quickly. Many such tools are prototypes. Six weeks later, nobody may know how to change one safely, where its data lives, or what to do when it fails.

A hosted app builder can be fast, but the tool stays on that platform. A developer's kit can make work reliable, but it expects the person to read code. AI Build Kit is designed for the space between those options. The person can change coding agent, host or developer later.

The kit suits internal tools used by people the owner names, such as a team, a club, a family or invited clients. Its proven setup keeps each tool private by default. Public features are possible when the person asks for them, hears the risks and records the choice. A tool that takes money from strangers is public-facing.

The kit does not suit someone who wants an app in ten minutes and never wants to use GitHub. A hosted builder may suit them better. The kit does not teach programming or replace a developer when one is needed. It runs no service of its own and keeps no project records outside the person's project. A project may need a professional for work that calls for one.

## How the work is controlled

The person creates and owns the accounts. The kit does not create them. A recipe names any service the tool uses, and the owner holds those accounts.

At setup, the kit records what failure could cost. It asks who could be affected, what data the tool holds and how the owner could recover. It also names the kinds of risk that apply. Each piece then names the risk areas it touches. Some rules protect every project and cannot be waived.

## How the kit is checked

The mutation run breaks one promise at a time. It reports which checks notice the broken promise.

Release verification builds the release again and compares it with the version prepared for publication. This checks that the files ready to ship match the reviewed release.

These checks give evidence about the kit. They do not prove that every tool built with it is safe or right for every purpose. A check that did not run never counts as a pass.

[See how the kit tests itself](/ai-build-kit/what-it-checks/#how-the-kit-tests-itself).
