v0.20.2 fixes GitHub access during founding and the first code upload, including Codex sessions on macOS.

The GitHub permission checks apply to every project. The launcher changes apply to Codex, and the shell configuration offer appears only during setup on macOS.

## Updating

Type `/maintain` in your project and accept the kit update. Start a new session afterwards, so it reads the new skills.

In Codex, run `/maintain` again if you want it to offer the new GitHub check at session start. Adding that check requires your approval.

If you are still on v0.19.3 or older, follow the [v0.20.0 update steps](https://github.com/gwpicard/ai-build-kit/releases/tag/v0.20.0) to finish the move to six commands.

## What changes

1. **Codex can use your existing GitHub login.** The kit gives Codex a session launcher that does this. When the session cannot read the login, the kit gives you the exact restart command. On a Mac, founding can also offer to make typing `codex` use that launcher in kit projects. It asks for your approval before it changes your shell settings.

2. **Setup warns when your GitHub login lacks permission to upload workflows.** Founding carries on. `/implement` checks again before it asks for the first upload. To fix the login, run this in your own terminal: `gh auth refresh -h github.com -s workflow`. It opens the browser once. In Codex, quit and restart through the launcher that the kit shows. Then the session uses the updated login. If you use SSH, or the kit cannot read your permissions, the kit shows the result as unknown.

## What was tested, and what is not proven yet

- Source checks and rehearsals cover the launcher, the install routes, the reading of permissions and the recovery messages.
- A real Codex run on macOS completed founding and the first upload. Local tests, type checking and linting passed.
- GitHub could not start the remote check of that test project, because of a billing or spending limit on the account.
- The browser permission refresh was not tried against a real account.
