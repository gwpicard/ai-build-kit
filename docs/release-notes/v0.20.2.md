v0.20.2 fixes GitHub access during founding and the first code upload, including Codex sessions on macOS.

## Updating

Type `/maintain` in your project and accept the kit update. Start a new session afterwards so it reads the new skills. In Codex, run `/maintain` again if you want it to offer the new GitHub check at session start; adding that check needs your yes.

If you are still on v0.19.3 or older, follow the [v0.20.0 update steps](https://github.com/gwpicard/ai-build-kit/releases/tag/v0.20.0) to finish the move to six commands.

## What changes

Codex can use your existing GitHub login through the kit's session launcher. When the session cannot read the login, the kit gives the exact restart command. Founding on a Mac can also offer to make typing `codex` use that launcher in kit projects, with your approval before changing your shell settings.

Founding now warns when the GitHub login lacks permission to upload the automated checks. It carries on, and `/implement` checks again before asking for the first upload. The recovery command is `gh auth refresh -h github.com -s workflow`, run in your own terminal. It opens the browser once. In Codex, quit and restart through the shown launcher afterwards so the session uses the updated login. SSH and permissions the kit cannot read are left unknown.

## Evidence and limits

The source checks and rehearsals cover the launcher, installation routes, permission reading and recovery messages. A real Codex run on macOS completed founding and the first upload with local tests, type checking and lint passing. GitHub could not start that disposable project's remote check because of the account's billing or spending limit. The browser permission refresh itself was not rehearsed against a real account.
