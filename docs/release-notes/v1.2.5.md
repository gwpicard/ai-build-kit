v1.2.5 corrects the kit's public documentation so it matches what the kit's scripts do, fixes the Codex installation steps on a Mac, and gives every installation route a written way to start a fresh reviewer.

**Who gets what.** Every project that updates gets the reviewer change and the two corrected references. The documentation changes are on GitHub and the documentation site, not in your project.

## Updating

Run `/maintain` in an existing project. It names the new version, summarises these notes and asks for your approval before it updates. After the update, start a new session, so the agent reads the changed skills. No other action is required, and the update does not change your tool's data.

## What changes

1. **Codex on a Mac installs in the right order.** The installation page told a Codex user on a Mac to start Codex through the session launcher before installing the kit, but the launcher arrives with the installation. The README, the installation page and `llms.txt` now give the same order: install the kit for this project from a terminal, start each Codex session with `python3 .agents/skills/setup-ai-build-kit/scripts/codex-with-github.py`, then ask Codex to run setup. In an empty folder, this order installed the kit, started Codex with GitHub access, and passed setup's first check.

2. **Documentation that matches the scripts.** A review of every public page checked each claim against the kit's code, and the confirmed errors are corrected. For example:

   - The site no longer says that one server can host several tools.
   - The comparison page now cites the right source for Lovable's publishing scan, and says that Base44 syncs with GitHub both ways on some plans and does not support self-hosting.
   - The plugin listings no longer promise "reliable software".
   - The compatibility page no longer says that a check restores files a reviewer changed, because no such check runs at present.
   - The compatibility page no longer says that `/maintain` finds edits you made to the kit's skills before an update. It requires a clean checkpoint, which does not catch edits to the kit's skills that you have already committed.

3. **A fresh reviewer on every installation route.** The shared skills installer and the Agent Plugins folder do not install the kit's agents. On those routes, the review skill now says how to start an ordinary fresh agent and which skill it loads. The skills also agree that a review covers a piece's change and, at founding, the masterplan.

4. **Two corrected references.** The live-copy skill and the Coolify recipe's live check now say that `/host` belongs to the Coolify companion tool, not to the kit. A reference in the repair script now points to the repair instructions that exist.

5. **Security reports have a private route.** The security policy asks you to report a vulnerability through GitHub's private vulnerability reporting, which is now switched on for the repository.

## What was tested, and what is not proven yet

- On GitHub, the source checks, the site build and its link check, and all 101 rehearsals pass.
- Replayed conversations covered founding, review, merging and maintenance, with 26 graded runs across 13 scenarios on a candidate with the same founding and review instructions. Two further runs, of updating an older project, could not start and were not graded. No failure was traced to this release. Two failures were also seen in earlier runs, and are recorded for later work. One is that the agent sometimes moves unsaved work out of sight before a change, instead of stopping to ask.
- A check that restores files a reviewer changes, and a check for your own edits to the kit's skills before an update, were built for this release but held back for further work.
- No real run of either recipe has yet restored a backup.
