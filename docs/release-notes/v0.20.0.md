v0.20.0 cuts the kit from nine commands to six, and the agent now asks you before it merges a pull request.

This reaches every project. Nothing you built changes. Four old commands are gone, and their jobs moved into other commands.

## Updating

Complete all three update steps:

1. **Type `/maintain` in your project.** It reads these notes and asks before it updates the kit. Say yes. It uses the same route you installed with.
   - In Claude Code, with the plugin, you can also run `claude plugin marketplace update ai-build-kit`, then `claude plugin update ai-build-kit@ai-build-kit --scope local`.
2. **Start a new session.** In Claude Code, `/reload-plugins` also works. The session that ran the update still uses the old kit, so it cannot finish the move.
3. **Type `/maintain` again.** This visit finishes the update. Each change requires your approval, and you can decline any of them:
   - remove the old `/fix`, `/queue`, `/sync` and `/ship` skills. With the shared installer, this runs `npx skills remove fix queue sync ship`;
   - rewrite the command list in your `AGENTS.md`;
   - add the newer safety rules to your Claude Code settings;
   - replace the kit's own helper files. It does this after a saved checkpoint, so you can go back.

**You are done when** `/what-now` no longer says "The kit update is not finished."

Until you do step 3, the old commands are still on offer. `/what-now` and `/implement` say that the update is not finished. You can continue working while the update remains unfinished.

## What changes

1. **Six commands, not nine.** The table shows where each job went.

   | You want to | Before | Now |
   |---|---|---|
   | Start a project | `/setup-ai-build-kit` | `/setup-ai-build-kit` (no change) |
   | Turn a request into a piece of work, new or broken | `/shape`, or `/fix` for a bug | `/shape` |
   | Build a ready piece | `/implement` | `/implement` |
   | See what can be built at the same time | `/queue` | `/implement` |
   | Repair something that broke | `/fix` | `/shape` finds the fault, then `/implement` repairs it |
   | Put the tool live, or check the live copy | `/ship` | `/setup-hosting` |
   | Bring the records up to date | `/sync` | `/maintain` |
   | Regular upkeep | `/maintain` | `/maintain` (now also does what `/sync` did) |
   | Find out where you are | `/what-now` | `/what-now` (no change) |

2. **Merging requires explicit approval.** `/implement` builds the piece and shows you the result. It merges only after an instruction that explicitly approves the merge, such as "merge it". "Put it live" alone prompts a separate merge question.

3. **On the supported hosting recipes, merging deploys the change.** The host builds each change to `main`. After merging, `/implement` checks the live deployment once to confirm that the change arrived.

4. **Claude Code asks for confirmation before each merge.** Confirm the merge in the dialogue. This requires the safety rules from step 3. Until you add them, the kit relies on your explicit approval in the chat and reports that limitation.

5. **The kit prohibits force pushes and forced recursive deletion.** Claude Code's deny rules cover more command forms, including options placed later in the command. Other agents rely on their permission settings and the kit's instructions. The blocked-command reference records the remaining gaps in enforcement.

6. **Database and hosting requirements must be prepared before merging.** If a piece adds database structure or needs a new secret or service, `/implement` waits while `/setup-hosting` prepares the live environment. These additions must remain compatible with the version currently running.

7. **`/setup-hosting` never merges code.** You run it to set up hosting. You run it again later to compare the live copy with `main`. Each later run adds one dated line to your changelog, even when it finds nothing wrong.

8. **A failure after deployment prompts a rollback offer first.** Where the previous version worked and a recipe rollback is available, the kit offers to restore it with your approval. Then `/shape` investigates the fault and `/implement` builds the repair.

9. **A new project tells you what it will do on GitHub** before it opens the first issue. On a public repository, it warns you that your plan will be public. Then it carries on.

## What does not change

- Your code, `masterplan.md`, `CHANGELOG.md`, issues and hosting stay as they are.
- Your own notes may name an old command, such as "we run /ship on Fridays". `/maintain` points to the line once. It never rewrites your words.
- Skill folders you changed yourself stay untouched. So does anything reached through a link outside the project.

## What was tested, and what is not proven yet

- Update rehearsals covered shared installations, whole copies of the kit and the Claude Code plugin.
- A real `/maintain` update on a real older project is not yet tested in a real session.
- The update through Agent Plugins is not yet tested.
- Several people working at the same time, and a merge conflict, are not yet tested.

If the update fails, open an issue on the AI Build Kit GitHub page and include your installation route.
