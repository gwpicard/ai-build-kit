After updating, start a new session (or /reload-plugins) and type /maintain again.

## In short

The kit now has six commands, not nine. Four old commands are gone, and their
jobs moved into other commands. An agent now asks you before it merges a pull
request. Nothing you built changes.

You update in three steps, and the third step is the one people forget.

## How to update

1. **Type `/maintain` in your project.** It reads these notes and asks before
   it updates the kit. Say yes. It uses the same route you installed with.
   - In Claude Code, with the plugin, you can also run
     `claude plugin marketplace update ai-build-kit`, then
     `claude plugin update ai-build-kit@ai-build-kit --scope local`.
2. **Start a new session.** In Claude Code, `/reload-plugins` also works. The
   session that ran the update still uses the old kit, so it cannot finish the
   move.
3. **Type `/maintain` again.** This visit finishes the update. It asks before
   each change, and you can say no to any of them:
   - remove the old `/fix`, `/queue`, `/sync` and `/ship` skills. With the
     shared installer, this runs `npx skills remove fix queue sync ship`;
   - rewrite the command list in your `AGENTS.md`;
   - add the newer safety rules to your Claude Code settings;
   - replace the kit's own helper files. It does this after a saved
     checkpoint, so you can go back.

**You are done when** `/what-now` no longer says "The kit update is not
finished."

Until you do step 3, the old commands are still on offer, and `/what-now`
and `/implement` say that the update is not finished. Your work goes on as
normal. Nothing waits for it.

## What to type now

| You want to | Before | Now |
|---|---|---|
| Start a project | `/setup-ai-build-kit` | `/setup-ai-build-kit` (no change) |
| Turn a request into a piece of work, new or broken | `/shape`, or `/fix` for a bug | `/shape` |
| Build a ready piece | `/implement` | `/implement` |
| See what can be built at the same time | `/queue` | `/implement` |
| Repair something that broke | `/fix` | `/shape` finds the fault, then `/implement` repairs it |
| Put the tool live, or check the live copy | `/ship` | `/setup-hosting` |
| Bring the records up to date | `/sync` | `/maintain` |
| Regular upkeep | `/maintain` | `/maintain` (now also does what `/sync` did) |
| Find out where you are | `/what-now` | `/what-now` (no change) |

## What changes for you

**Merging now asks you first.** `/implement` builds a piece, shows it to you,
and merges it only when you say a yes that names the merge, such as "merge
it". "Put it live" alone is not enough. It asks again.

**On a live project, a merge is going live.** Your host builds every change
that reaches `main`. So the merge that `/implement` makes is the deploy. After
the merge, `/implement` reads the live copy once to confirm the change arrived.

**Claude Code shows a box before each merge.** You click to allow it. This
needs the new safety rules from step 3. Until you add them, the merge runs on
your yes in the chat, and the kit tells you so.

**A force push is always refused.** So is a forced delete. The kit stops these
however the command is written.

**Some changes wait for the live side first.** If a piece adds to the
database, or needs a new secret or a new service, `/implement` does not merge
it yet. `/setup-hosting` first adds that to the live side. Then the merge
goes ahead. The version that is live keeps working the whole time.

**`/setup-hosting` never merges code.** You run it to set up hosting, and
again later to compare the live copy with `main`. Each later run adds one
dated line to your changelog, even when it finds nothing wrong.

**When the live tool breaks right after a merge,** the kit first offers to put
back the earlier version. It does this only after your yes. Then `/shape`
finds the fault and `/implement` repairs it.

**A new project tells you what it will do on GitHub** before it opens the
first issue. On a public repository it warns you that your plan will be
public, then carries on.

## What does not change

- Your code, `masterplan.md`, `CHANGELOG.md`, issues and hosting stay as
  they are.
- If your own notes name an old command, such as "we run /ship on Fridays",
  `/maintain` points to the line once. It never rewrites your words.
- Skill folders you changed yourself, and anything reached through a link
  outside the project, stay untouched.

## Not yet tested

- A real `/maintain` update on a real older project. The update ran in
  rehearsals on every install route, but not yet in a real session.
- The update through Agent Plugins.
- Several people working at the same time, and a merge conflict.

If the update goes wrong for you, please open an issue at
https://github.com/gwpicard/ai-build-kit/issues and say which install route
you use.
