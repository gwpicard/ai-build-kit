v0.20.3 fixes seven things that a real project ran into while it was built with the kit.

This reaches every project. One exception: a project founded before this release keeps GitHub's squash and rebase merges switched on in its repository settings. The kit no longer uses them either way.

## Updating

Type `/maintain` in your project and accept the kit update. Start a new session afterwards, so it reads the new skills. Nothing else is needed.

If you are still on v0.19.3 or older, follow the [v0.20.0 update steps](https://github.com/gwpicard/ai-build-kit/releases/tag/v0.20.0) to finish the move to six commands.

## What changes

1. **A check that GitHub will not start is no longer called a failure.** This happens, for example, when a billing limit on the account stops it. The kit now runs the same checks on your computer and tells you once. On a private exploration, that is enough to merge. On the other two paths, the merge waits until GitHub runs the check. The check is switched off only if you ask. `/maintain` reminds you while it stays off.

2. **A merge keeps every commit of the piece.** Founding also turns off GitHub's squash and rebase merges on a new repository.

3. **A piece's labels are right after it merges.** `ready` becomes `building` when the build starts. Both labels are gone once the piece closes.

4. **Founding records which version the masterplan was written against.** Later builds can then keep that record up to date. If a project has no such record, `/what-now` points you to `/maintain` to make one.

5. **`/shape` never starts a build because you picked one of its answers.** A build starts only when you ask for it.

6. **The kit asks where extra requests go.** Suppose you ask for more while a piece is being built. The kit first asks whether the request belongs in this piece or in a new one. It asks to merge only after you have tried the result.

7. **Previews are tidier during a build.** A build gives you one address to try the work on. It stops any older preview first. It checks pages in a browser tab of its own, not in yours. It stops its previews when you are done.

## What was tested, and what is not proven yet

- Each change has a source check that fails when its rule is removed. All 93 rehearsals pass.
- Before release, two throwaway projects were founded and built with Claude Code from a preview. Every change above held there, except two that the run did not reach.
- Not reached: a private exploration that merges on the local checks alone, and `/what-now` pointing to `/maintain`.
- That run also found four older faults. They are written up for the next release.
