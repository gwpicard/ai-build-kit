v1.1.0 adds a companion site for the kit, corrects the documentation to match what the kit does in 1.0, and makes one change to how a recipe merge handles a health check that could not run.

## Updating

Type `/maintain` in your project and accept the kit update through your existing installation route. Start a new session afterwards so it reads the new skills. Nothing else is needed.

If you turned on automatic merge in 1.0 and added the local Claude rule `Bash(python3 *merge.py --auto *)`, you can remove that rule. Automatic merge no longer needs it.

## What changes

- The kit has a companion site at https://gwpicard.github.io/ai-build-kit/. It explains how to install the kit, the workflow and what is checked at each step, the rules checked in every project, the hosting recipes, how the kit compares with other tools, and the sources of its ideas.
- On both recipes, a merge now waits when the container health check could not run on your computer. Before, the agent said so and merged on your approval. A failed check still holds the merge, as before.
- The skills now describe automatic merge consistently. A merge needs your approval by default, and it happens without one only when you have turned automatic merge on and the merge script finds that its conditions hold.
- The documentation no longer uses terms that 1.0 retired, such as private exploration and the sensitive-area step.
- The documentation now states only what each recipe's real run recorded. The Vercel run recorded going live, a health check and two database migrations. The Coolify run recorded preview, launch, rollback, secrets, logs and health. Backup and restore have not yet had a real run on either recipe.
- The quarterly check of a project's services now compares the products your project uses with their documentation. The recipes themselves are kept current with the kit.
- The first-upload page now gives the exit code the script really uses when the repository has no branch (3, not 2), so the agent reads that state correctly and asks for your yes before the first upload.
- Where you turn on automatic merge, the agent now writes the `Runs on its own:` line in the order the merge script reads: `merge`, then `decided` and a date, then your words in double quotes. Before, a line in another order left automatic merge off, and the merge script stopped with a message that the setting was missing.
- When founding checks the working conditions and `main` already exists on GitHub, the agent now says that it also applies branch protection to `main`.

## Evidence and limits

All 95 source checks pass. A new check fails when a link on the site points at a missing file or section, and the source check now fails if a retired 1.0 term returns to any shipped file or site page. No replay was run for this release. The health-check change is a rule the agent follows; no script or replay checks it yet.
