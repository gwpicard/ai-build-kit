v1.1.0 adds a companion website for the kit, corrects the documentation to match what the kit does in v1.0, and changes how a recipe merge treats a health check that could not run.

Every project gets the skill changes. The website is public and needs no update.

## Updating

Type `/maintain` in your project and accept the kit update through your existing installation route. Start a new session afterwards, so the agent reads the new skills. Nothing else is needed.

If you turned on automatic merge in v1.0 and added the local Claude rule `Bash(python3 *merge.py --auto *)`, you can remove that rule. Automatic merge no longer needs it.

## What changes

1. **A companion website.** The kit now has a site at https://gwpicard.github.io/ai-build-kit/. It explains how to install the kit, the workflow and what is checked at each step, the rules checked in every project, the hosting recipes, how the kit compares with other tools, and where its ideas came from.
2. **A merge waits when the container health check cannot run.** This applies to both recipes. The health check starts the tool in a container on your computer. Before, if it could not run, the agent said so and merged on your approval. Now the merge waits. A failed check still holds the merge, as before. This is a rule the agent follows. No script or replay checks it yet.
3. **Automatic merge instructions now agree.** Merges require your approval by default. Once you enable automatic merge, the script can merge eligible changes under the limits you approved.
4. **The automatic merge setting now uses the required field order.** When you turn on automatic merge, the agent writes the `Runs on its own:` line in the order the merge script reads. The order is `merge`, then `decided` and a date, then your words in double quotes. Before, a line in another order left automatic merge off. The merge script then stopped with a message that the setting was missing.
5. **First-upload guidance now recognises an empty repository correctly.** The page now documents exit code 3 for a repository with no branch, correcting the previous value of 2. The agent can then request your approval before the first upload.
6. **Setup now reports when it applies branch protection.** When `main` already exists on GitHub, setup explains that the working-condition check also applies branch protection where the account plan supports it.
7. **Documentation matches v1.0.** The documentation no longer uses terms that v1.0 retired, such as private exploration and the sensitive-area step.
8. **Recipe documentation now separates tested outcomes from untested steps.** The Vercel run recorded going live, a health check and two database migrations. The Coolify run recorded preview, launch, rollback, secrets, logs and health. Backup and restore have not yet had a real run on either recipe.
9. **Quarterly maintenance now checks the services your project uses against their documentation.** Recipe updates are maintained with the kit.

## What was tested, and what is not proven yet

- All 95 of the kit's own checks pass.
- A new check fails when a link on the site points at a missing file or section.
- The kit's check now fails if a retired v1.0 term returns to any shipped file or site page.
- No replay of scripted conversations was run for this release.
- The health-check change has no script or replay that checks it.
