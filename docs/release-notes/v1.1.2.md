v1.1.2 fixes the health check so it accepts the starter's real answer, and makes the documentation say only what the checks prove.

**Who gets what.** The health check fix affects projects that use the starter's health route on either recipe. The documentation changes reach every project.

## Updating

Run `/maintain` to update an existing project. No data migration is required.

## What changes

1. **The health check accepts the starter's real answer.** The starter reports `database: "reachable"`. The old health reader rejected that answer from the live Vercel deployment. The fixed reader accepts it. It still accepts the older answer, `database: "ok"`.
2. **The local container check is stricter.** The agent starts the tool in a container on your computer. The check needs two results. With a good database address, the answer must be HTTP 200 with the database reachable. With an invalid database address, the answer must be HTTP 503. Before, a failed request or a failed container start could count as a successful 503. Now it does not.
3. **A shorter recipe page.** The public recipe page combines explanations that overlapped. It states the remaining gaps in testing together.
4. **Instructions match the checks.** The setup, review and deployment instructions now describe only the results that the checks confirm.
5. **Hosting plan advice is more careful.** The guidance now points to the supplier's terms. The reader chooses the plan.

## What was tested, and what is not proven yet

- The health check was tested against the starter's real health route, both recipe rehearsals, and a real container on one computer that gave HTTP 200 and HTTP 503. It was also tested against the existing Vercel deployment's healthy answer. No hosted service changed during these tests.
- All 95 rehearsals on a clean copy, the adapter checks and the source checks pass.
- The mutation audit found all 144 faults it planted in the shell tests. It lists three more cases separately, because replays own them. Those three were not run as conversations.
- The prepared release archive matches the local build: all 552 files and their executable permissions.
- The skill text is 30,568 words, against 30,521 in v1.1.1.
- No new replay of conversations was run for this patch. The earlier replay results are history.
- The starter's test tools have known security advisories. They are recorded in a follow-up issue on the project's GitHub page. This patch does not update those packages. It does not claim a clean dependency audit.
