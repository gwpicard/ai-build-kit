# Quarterly upkeep

Read the official documentation and changelog for every product named in each
recipe and part. Keep a dated note in the ignored folder. Carry agreed changes
into the recipe and this guide. Move `Last checked` only when every product
was read.

Run the monthly routine first. Review hot spots: repeated changes or bugs,
weak evidence, edits that touch many files, failing integrations and records
that no longer explain reality. Run
the waste, structure and document-bloat reads from `quality-checks`. Propose
up to three simplifications with the problem, change, benefit, cost and any
outside review needed. Apply only on approval.

Review project skills and offer to remove instructions that no longer pay
    their way. Run the `evidence-run` skill for the risk record and its risk areas.
Check whether the team can explain main flows, verify changes without code,
find data, secrets, owners and bills, recover or use a fallback, and whether
reliance or risk areas have changed.

For a new or newly bounded area, offer
`quality-checks/references/boundary-rules.md`. Remove an area only after a
redesign removes its cause. Prepare a handover when asked or when a caution
names a person the team must find. Update `last-full-pass` and
`last-light-pass`.
